How a lab report becomes chartable data

02

Parsing: what OpenParser returns

OpenParser is a hosted document-layout model. Given a page it returns blocks — what each region is, where it sits, and what it contains. Crucially, it returns tables as HTML: it has already decided where the cell boundaries are, which is the hardest part of reading a printed table and the part a coordinate-only OCR leaves to you.

Why a model, not classical OCR

These pages are thermal receipts, carbon copies, faxes and phone photographs. Cell boundaries are often not drawn at all — the layout is implied by spacing, and only a layout model recovers it.

Why the raw response is kept

Every response is written to disk beside the document. A pipeline change then replays 300 documents in seconds for nothing, instead of 40 minutes and a bill. Ideas get tried and thrown away.

What skips it entirely

A PDF with a real text layer already contains the characters. Rasterising them to ask a model what they say is slower and strictly less accurate, so those are read directly with pdfplumber.

Everything arrives with a confidence and a bounding box. The box is what makes click-to-highlight possible on the review screen: a reviewer clicks a row and the page scrolls to where it was printed. Confidence below a threshold is surfaced to the reviewer rather than used to silently discard anything.
03

Converting: from blocks to rows

This is where most of the difficulty lives. A printed table has no schema. Nothing declares which column holds the result and which the reference range, and labs disagree about the order. So each column is profiled by what it contains.

RoleIdentified byClaimedWhy that order
LabelWordy, nearly all distinct values1stLeftmost match wins, so a serial-number column cannot become the result
ReferenceTwo-sided ranges — 13.0 - 17.02ndThe least ambiguous thing on the page
UnitUnit lexicon, then a shape heuristic3rd—
FlagMostly empty; non-empty cells all markers4thThe blankness is the signal
ValueBare numbers, after stripping flag and unit5thClaimed from what is left

Method lines get folded up

Method : Diazo on its own line is a continuation of the test above it, not a result. Folding it stops a twelve-analyte panel arriving as twenty-four rows.

Units ride in the reference cell

Many labs print no unit column at all and write 35-104 U/L. The unit is recovered from there, because a value without a unit cannot be trended.

Headers are separated from results

A bordered demographics box is a table too. Read as results it loses the patient; a whole table is promoted to header only when every row pairs and at least two keys are known.

05

Panel templates, and finding the patient

What extraction cannot answer about itself

An extractor knows what it found; it cannot know what it missed. A template says which analytes a named panel should contain. Seventeen templates cover the panels Indian clinics actually order, and comparing template against result yields three different problems.

missing

The template expects it, the report did not yield it. Either the lab did not run it, or extraction dropped it. Only a missing core member counts against a document.

unexpected

An analyte the template does not list. Usually a legitimate add-on, occasionally noise.

unresolved

A label that matched no canonical code. The vocabulary's gap, not the extractor's — reported as a finding, not a failure.

Core versus optional is not decoration. Indian labs sell a thyroid panel as T3/T4/TSH, or with the free forms added. A flat expected-list would report a perfectly good extraction as a failure on half the market.

Which patient is this?

Only an exact UHID attaches a document without a human. A demographic match is capped below certainty by construction — two patients at one clinic can share a name and a birth year, and a name is not an identifier the practice issued. A printed sex that contradicts the record disqualifies the candidate outright rather than merely scoring low: the same person does not change sex between requisition and report.

Functions, not ORM SQL

Validation lives next to the constraint it protects, and the API cannot forget practice_id. Bulk-confirming 256 documents calls the function 256 times rather than issuing one UPDATE, so the audit trail is identical to doing them by hand.

No native enums

VARCHAR with a CHECK. Changing a CHECK is a migration; changing an enum is an outage.

BigInt keys, strings in the UI

BIGINT runs to 263; JavaScript loses precision above 253. Parse one into a number and a patient id can change value silently — which here means filing a report against the wrong person.

One thing that is not enforced. practice_id is on every lab table and has no foreign key behind it. Tenancy is upheld entirely by application code — every query filters on the caller's practice. Deliberate, and load-bearing: a combination worth knowing rather than discovering.
07

Two problems, and what they cost

Both were found by measuring, not by reading code. Both had been quietly wrong for the whole life of the project.

One · A narrow page prints its table sideways

A thermal receipt is too narrow for columns, so labs print label above value — and OpenParser returns that faithfully, one cell per row. The extractor expected columns. It assigned every cell to label, produced rows with no values, and the header pairer — which needs two cells to see a pair — found no patient and no UHID either. A single unrecognised header key, Report Released, was enough to sink the entire header table.

Fix: fold the grid into two columns before anything reads it, so nothing downstream needs to know the shape exists.

thermal-slip precision 26.3% → 100.0% UHID recovered on pages that previously yielded none

Two · A unit in the value cell made the value unreadable

Many labs print no unit column and write 12.9 g/dL in the value cell. Column inference asks whether a column holds bare numbers; the unit made the answer no, the column was typed unknown, and every reading on the panel was dropped. The profiler already stripped a trailing flag for exactly this reason, with a comment explaining that not doing so "silently dropped every abnormal panel". Nobody had applied the same reasoning to a trailing unit.

value accuracy 85.2% → 95.6% ≈ 380 readings corrected recall and precision unchanged

The largest correctness gain in the project, and the failure mode the system fears most: those rows were on the right chart, under the right patient, with the wrong number.

The recall targets were missed because the premise behind them was wrong. Folding the grid was expected to recover both the header and the values on narrow pages; it recovers the header. The values on those pages were never the problem — the phantom rows were. Reporting that is the point: a number nobody can check is worth less than a smaller number somebody can.
