01

The question

OpenParser returns the same JSON shape for every document: a list of pages, each holding blocks with a label, a bounding box and some content. Sometimes that content is an HTML table. Sometimes it is a loose line of text. The information we need is present either way, so the question is whether we can pull it out either way.

02

Where we actually stand

Every one of the 303 documents was re-read on 25 September against the current code. Grouping the outcome by the print style each document imitates gives the clearest picture we have of what breaks.

The finding that changes the plan

Poor scans, phone photos, carbon copies, fax headers, dot-matrix pinfeed and manual typewriter output all extract at 100%. Degraded print quality — the thing we worried about for tier-2 and tier-3 cities — is not what breaks the pipeline.

What breaks it is shape. A receipt-shaped slip, a screenshot of a chat, a fully handwritten page. The failures cluster in four formats and nowhere else.

degraded print → 100% unusual format → 0–85% 26 of 303 documents empty
Caveat worth stating. This corpus is synthetic. Its poor_scan and mobile_photo styles model degradation we invented. A real photo taken in poor light in a Jaipur clinic may be worse than anything here. The result above says our handling of simulated degradation is sound; it does not prove the same of real degradation, and we should re-measure once real uploads exist.
03

Why the thermal slips fail

Not because the engine cannot read them. Because our pipeline builds result rows only from <table> HTML, and a receipt-shaped page produces no table. The values sit in the response, unread.

We already own every piece this needs. split_value_unit(), split_flag_suffix() and looks_like_flag() were built for the table path and work unchanged on loose text. If loose blocks are folded into the same grid shape a table produces, then column-role inference, analyte resolution and the coverage check all run without modification.

07

The recommendation

Three passes over the same block JSON, each cheaper and more certain than the one after it. We already own the router: the coverage check that reports missing, unexpected and unresolved analytes is exactly the signal for "this document did not extract properly".

Pass B — build this now

Fold loose blocks into the grid shape tables already produce, then let column-role inference, analyte resolution and coverage run unchanged. No new dependency, no vendor, no per-document cost, every value traceable to a bounding box.

Pass C — design, do not build

An LMDX-style prompt: each block suffixed with quantised coordinates, the model required to name the block it read each value from. Anything that fails to ground is discarded, so a fabricated potassium value cannot survive. Decide after Pass B's numbers are in.

Do not use JSON mode

Constrained decoding costs 3–9 points of accuracy across open-weight models, and one benchmark saw validity fall from 51% to 37% under structured output. Generate freely, then check grounding. The check is the guarantee, not the schema.

The honest summary. We are at 100% on twenty-two of twenty-six print styles, including every degraded-print style we tested. One format — the thermal slip — accounts for 17 of our 26 total failures, and it fails for a reason entirely inside our own code. Fixing it needs no new vendor, no new budget line and no data-protection decision.
